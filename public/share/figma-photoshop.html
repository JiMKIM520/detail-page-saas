피그마 → 포토샵, 레이아웃이 깨지는 이유

피그마에서 편집한 시안을 포토샵으로 넘기면 레이아웃이 어긋나는 문제를 조사했습니다. 원인이 하나가 아니라 셋이 겹쳐 있고, 그중 둘은 오늘 바로 없앨 수 있습니다.

2026-08-07 · 하나파워온스토어 레벨업 상세페이지 · 가로 860px · 세로 7,000px 이상

가장 큰 원인은 폰트입니다. 피그마는 웹폰트를 서버에서 받아 그리지만, 포토샵은 PC에 설치된 폰트만 봅니다. 우리가 쓰는 한국어 36종이 디자이너 PC에 없으면 포토샵은 다른 폰트로 바꿔 버리고, 글자 폭이 달라지면서 줄바꿈이 밀리고 그 아래가 전부 어긋납니다.

두 번째는 좌표입니다. 피그마는 y: 1456.5 같은 소수점 위치를 허용하고, 오토 레이아웃을 쓰면 저절로 생깁니다. 포토샵은 이를 반올림하는데, 요소마다 반올림 방향이 달라 1~2px씩 어긋난 것이 7,000px를 내려오는 동안 쌓여 눈에 띄게 벌어집니다.

세 번째는 오토 레이아웃 자체입니다. 포토샵에는 대응 개념이 없어, 옮기는 순간 모든 요소가 절대 좌표로 굳습니다. 내용에 따라 높이가 늘어나던 텍스트 박스가 피그마가 계산한 위치와 다른 자리에 놓입니다.

원인별 영향도

조사에서 확인된 순서대로

한국어 웹폰트가 PC에 없음

영향 큼

피그마는 CDN에서 폰트를 받아 그리고, 포토샵은 OS 설치 폰트만 참조합니다. 우리가 쓰는 woff2는 웹 전용 포맷이라 포토샵이 아예 인식하지 못합니다. 데스크톱용 OTF/TTF를 따로 설치해야 합니다.

소수점 좌표 반올림이 누적됨

영향 큼

피그마가 허용하는 소수 좌표를 포토샵이 반올림합니다. 요소 하나로는 1px이지만 세로 7,000px에 걸쳐 수십 개가 각기 다른 방향으로 반올림되면 틈과 겹침이 눈에 띄게 쌓입니다.

오토 레이아웃이 절대 좌표로 굳음

영향 큼

포토샵에 오토 레이아웃 개념이 없어 패딩·간격 계산이 사라지고 위치가 고정됩니다. 특히 높이가 유동적인(hug) 텍스트 박스에서 어긋남이 큽니다.

줄간격·자간 계산 방식이 다름

영향 보통

피그마는 줄간격을 CSS 방식으로 위아래 균등 분배하고, 포토샵은 글자 시각 경계를 기준으로 잡습니다. 같은 숫자를 넣어도 박스 높이가 달라집니다. 자간은 피그마 % × 10 = 포토샵 트래킹으로 환산됩니다(5% → 50).

피그마가 큰 이미지를 자동으로 줄임

영향 보통

한 변이 4,096px를 넘는 사진은 피그마에 올리는 순간 자동 축소됩니다. 고해상도 제품 사진이 피그마 진입 시점에 이미 흐려지고, 내보낸 결과도 흐린 채로 나옵니다.

색 프로파일 불일치

영향 보통

피그마는 sRGB로만 내보냅니다. 포토샵 작업 공간이 Adobe RGB로 잡혀 있으면 열 때 색이 달라집니다.

오늘 바로 할 수 있는 것

설치만 하면 되는 것과 설정 몇 개

  1. 36종 폰트를 OTF/TTF로 PC에 설치가장 큰 원인을 한 번에 없앱니다. 우리가 드린 woff2는 웹 전용이라 포토샵이 못 읽으므로, 각 폰트 배포처에서 데스크톱용 파일을 받아 설치해 주세요. 설치하면 피그마 데스크톱 앱도 로컬 폰트를 자동으로 인식합니다.
  2. 포토샵 색 공간을 sRGB로Edit → Color Settings → Working Spaces → RGB를 sRGB IEC61966-2.1로. PNG를 열 때 뜨는 창에서는 Use Embedded Profile(변환하지 않음)을 고르세요.
  3. 피그마에서 픽셀 그리드 스냅 켜기View → Snap to Pixel Grid. 내보내기 전 프레임의 X·Y·W·H가 모두 정수인지 확인하고, 소수가 보이면 정수로 고쳐 주세요. 오토 레이아웃 안쪽 프레임도 봐야 합니다.
  4. 저장은 Export As로Save for Web(Legacy)은 큰 이미지에서 다운샘플링이 일어납니다. File → Export → Export As를 쓰세요.
급하면 이 방법이 확실합니다 — 피그마에서 PNG 1배율로 통째 내보내 포토샵에서 열면 레이아웃이 100% 그대로 옵니다. 레이어와 텍스트 편집을 포기하는 대신 어긋남이 원천적으로 없습니다. 포토샵에서 사진 보정만 하신다면 이게 가장 안전합니다.

근본 해결 — 피그마를 건너뛰기

우리 파이프라인이 PSD를 바로 만드는 방안

기술적으로 가능하고, 3~5일이면 됩니다

지금 문제는 전부 피그마와 포토샵 사이에서 생깁니다. 우리가 처음부터 PSD를 드리면 그 구간이 사라집니다. 필요한 재료는 이미 다 있습니다 — 레이어별 이미지, 색·폰트 정보, 각 요소의 좌표를 파이프라인이 이미 만들고 있고, 조립할 라이브러리(ag-psd)도 검증된 것이 있습니다.

남는 작업은 자간·줄간격 단위 환산과 폰트 이름 매핑표 정도입니다. 텍스트 레이어가 살아 있어 포토샵에서 바로 고칠 수 있습니다.

다만 폰트 설치는 이 방법으로도 피할 수 없습니다. PSD의 텍스트 레이어는 폰트 이름만 갖고 있어서, 그 폰트가 PC에 없으면 포토샵이 대체 폰트로 바꿉니다.

먼저 판단하실 것이 있습니다. 포토샵에서 글자를 직접 고치시나요, 아니면 사진 보정만 하시나요? 글자 수정을 피그마에서 하고 포토샵에서는 보정만 한다면, PNG 1배율 내보내기로 충분해서 개발할 이유가 없습니다. 포토샵에서 글자를 자주 고쳐야 한다면 PSD 직접 생성이 확실히 이득입니다.

디자이너 확인 목록

  • 시작 전 한 번만
  • 36종 한국어 폰트를 OTF/TTF로 PC에 설치했다 (woff2는 포토샵이 못 읽음)
  • 포토샵 작업 공간이 sRGB IEC61966-2.1로 되어 있다
  • 피그마에서 내보내기 전
  • Snap to Pixel Grid가 켜져 있다
  • 프레임의 X·Y·W·H가 모두 정수다 (오토 레이아웃 안쪽 포함)
  • 텍스트 레이어의 Vertical Trim이 모두 None이다
  • 제품 사진이 한 변 4,096px를 넘지 않는다 (넘으면 흐려짐)
  • Pass-Through 블렌드 그룹을 Flatten 또는 Normal로 바꿨다
  • Corner Smoothing이 0%를 넘는 도형은 Flatten했다
  • 포토샵에서 열 때
  • PNG는 Export As로 내보냈다 (Save for Web 아님)
  • 색 프로파일 창에서 Use Embedded Profile을 골랐다
  • PSD 변환을 썼다면 텍스트의 폰트 이름·크기·자간을 피그마와 대조했다
조사에서 확인하지 못한 것 — Save for Web의 정확한 픽셀 한도는 자료마다 8,192px와 30,000px로 갈립니다. 어느 쪽이든 우리 7,000px 상세페이지는 범위 안이라 실무에 영향은 없습니다.
