# DetailAI 디자인 시스템 — 마스터 문서

> **지위**: 디자인 규칙의 단일 참조(Single Source of Truth). 에이전트(아트디렉터·페이지플래너·컴포저·평가자) 프롬프트와 렌더 계층 가드는 이 문서와 어긋나면 이 문서를 따른다.
> **강제 라벨**: `[가드]`=코드로 강제됨 · `[지시]`=프롬프트 선언만(위반 침묵 통과 가능) · `[부재]`=본 문서에서 신설(코드 미반영).
> **유래**: 2026-07-26 디자인 시스템 전수 감사(4방향)로 산재 규칙을 통합. 각 규칙 끝의 괄호는 코드 출처.
> **변경 절차**: 규칙 수정은 이 문서 먼저 → 코드·프롬프트를 문서에 정렬. 역방향 금지.

## 0. 디자인 철학 `[부재→신설]`

1. **제품이 주인공, 템플릿은 무대다.** 페이지의 인상은 브랜드·제품의 고유 속성(원료·질감·색·톤)에서 나와야 하며, 카탈로그 관례에서 나오면 실패다.
2. **모든 시각 요소는 근거를 가진다.** 카피가 브리프에 근거하듯, 이미지·색·장식도 제품 맥락에 근거한다. "예뻐서"는 근거가 아니다.
3. **다름은 기본값, 같음은 예외.** 연속 생성되는 페이지들이 같은 팔레트·같은 오프닝·같은 장식으로 수렴하면 시스템 결함으로 취급한다.
4. **자유는 게이트 위에서만.** 표현 자유도는 검증 게이트(스키마·대비·시각감사·평가자)가 받치는 범위에서만 확대한다. 게이트 없는 자유화 금지.
5. **정직이 프리미엄이다.** 무근거 수치·가짜 인증·과장 상투어보다 구체적 사실(온도·질감·시간·산지)이 더 고급스럽다.

## 1. 디자인 토큰

### 1.1 시맨틱 토큰 `[가드]` (2026-07-26 실코드 재동기화)
모든 변형 CSS는 하드코딩 대신 이 토큰(var(--…))을 참조해야 한다.
- **색** (shared.ts baseCss): `bg` `paper` `ink` `ink-2` `line` `brand` `accent` `accent-d` `muted` `em-dark` `scene-bg-1/2/3`
- **색·대비 보정** (composer.ts ACCENT_CONTRAST): `accent-fg`(다크 씬용 밝은 accent) `on-accent`(accent 배경 위 흑/백 자동)
- **폰트** (baseCss): `font-display` `font-body` `font-serif` `font-hand` `font-lat`(라틴·숫자 전용)
- **형태** (baseCss ← SHAPE_PRESETS): `r-scale` `shape-photo` `pad-x`

### 1.2 프리셋 4종 `[가드]`
`warm-playful`(친근 식품/생활) · `modern-editorial`(프리미엄 미니멀 명조) · `cobalt-premium`(모던 커머스/전자·뷰티) · `sand-luxury`(웜 뉴트럴 럭셔리). 브랜드색(로고→누끼 순 추출)이 있으면 brand 토큰을 오버라이드한다. (tokens.ts)

### 1.3 형태 언어 5종 `[가드]`
`sharp-editorial`(rScale 0.25) · `soft-round`(1.7) · `organic` · `arch-serif` · `neutral` — 아트디렉터 명시 > 무드 키워드 폴백. rScale/photoShape/padX로 변환된다. (tokens.ts SHAPE_PRESETS)
- **결정**: 신규 변형 CSS는 radius·좌우 패딩에 `var(--r-scale)`·`var(--pad-x)` 참조 필수. 하드코딩은 §5.4의 예외 신고 시에만. `[부재]`

### 1.4 폰트 화이트리스트 `[지시→승격 대상]`
아래 목록 외 폰트 지정 금지. (shared.ts FONT_WHITELIST — 유일 어휘. 아트디렉터 프롬프트의 목록과 불일치 시 이 목록이 정답)

- **Google Fonts**: IBM Plex Sans KR, Noto Sans KR, Noto Serif KR, Gothic A1, Sunflower, Stylish, Do Hyeon, Jua, Gowun Dodum, Nanum Myeongjo, Nanum Gothic, Nanum Pen Script, Nanum Brush Script, Hahmlet, Song Myung, Poor Story, Gamja Flower, Yeon Sung, Gugi, Hi Melody, Cute Font, Single Day, East Sea Dokdo, Kirang Haerang
- **클라이언트 제공**: SUIT, NanumSquare, MaruBuri, 가나초콜릿체, tvN 즐거운이야기
- 역할 4종(headline/story/body/accent): body는 산세리프 범용군만, 동일 폰트 다역할 금지, 페이지당 serif·sans 혼합 필수, 총 5종 이내. (art-director.ts, FONT_ROLE_LOCK)

## 2. 컬러 팔레트 조합 규칙

### 2.1 대비 하한 (WCAG 기반) `[가드]`
bg·paper ↔ ink **7:1** · brand 텍스트 **4.5:1** · accent(장식) **3:1**. 미달 시 프리셋 색으로 폴백. (tokens.ts contrastRatio)

### 2.2 팔레트 전략 어휘 `[부재→신설]`
아트디렉터는 매 프로젝트 아래 전략 중 하나를 **명시 선택**하고 그 이유를 designNotes에 기록한다. 특정 색 조합 예시를 각인시키지 않기 위해 전략은 **관계로만** 정의한다:
| 전략 | 정의 |
|---|---|
| `complementary-pop` | primary의 색상환 반대편에서 accent 선택 |
| `warm-cool-tension` | primary와 accent의 온도 대비(난색↔한색) |
| `metallic-accent` | 무채·저채도 primary + 금속성(골드·실버·브론즈) accent — **직전 3개 프로젝트에서 사용 시 선택 금지** |
| `tonal-depth` | 동일 색상 명도 계단 + 고채도 포인트 1색 |
| `category-native` | 제품 원물·패키지에서 실측 추출한 색을 primary로 승격 |
- accent는 primary의 단순 밝기 변형 금지. (art-director.ts)
- **금지**: 프롬프트·힌트에 구체 색 조합 예시("네이비+골드" 등)를 쓰는 것 — 예시가 각인되어 수렴을 유발한 실측 사례(7사 중 5사). 전략명과 관계 정의로만 지시한다.

### 2.3 다양성 규칙 `[부재→신설]`
같은 카테고리의 직전 프로젝트와 primary 색상군(12색상환 기준 인접 2칸 이내)·headline 폰트가 모두 겹치면, 둘 중 하나는 반드시 바꾼다. (런간 이력 참조는 Phase 2 구현 대상)

## 3. 레이아웃·컴포지션 규칙

### 3.1 씬(스크롤 단위) 높이 — **정렬 결정** `[가드+지시 불일치 해소]` (2026-07-26 재결정)
- **목표 범위**: 1,600~2,400px (플래너 설계 기준)
- **하드 한도**: **2,600px** — 설계 주체인 플래너의 검증 코드(validateBlueprint) 기준으로 통일. 초과 시 리밸런싱 개입.
- 2,400~2,600px는 "허용되나 개선 대상" — rule-check가 경고로 보고한다.
- 컴포저 리밸런싱 트리거(현행 2,700)는 2,600으로 정렬한다. `[Phase 1 반영 대상]`

### 3.2 톤 리듬 — **정렬 결정** `[지시 불일치 해소]`
- 카운팅 단위는 **씬**으로 통일한다(설계 주체가 플래너이므로). 페이지당 다크 씬 1~3개, 라이트 씬 3연속 금지, 인접 씬 톤 혼재 금지.
- 컴포저의 "다크 블록 2~3개" 규칙은 폐기하고 "플래너의 씬 톤 설계를 따른다"로 종속화한다. `[Phase 1 반영 대상]`

### 3.3 스케일 계층 `[지시]`
씬당 제목 스케일 ≥ 본문 3배(플래너) **그리고** 페이지당 풀블리드/statement급 대형 블록 1개 이상(컴포저) — 상보적 규칙으로 둘 다 유지. 서브타이틀 30px 하한, 본문 하한 23px 앵커. `[가드]` (FONT_ROLE_LOCK, remapFontScale)

### 3.4 히어로 `[가드]`
첫 블록은 hero/intro 계열 필수(스키마). 히어로 이미지 슬롯은 대표 연출컷 필수 — 비면 재배치 0순위가 기계 주입·승격(2026-07-24 가드 4겹 수정). 히어로 헤드라인은 스펙 나열 금지, 고객 변화·감각 1문장.

### 3.5 그리드 패리티 `[가드]`
대칭 2·3열 그리드의 아이템은 열수 배수 우선(근거 있는 포인트 발굴로). 홀수면 마지막 셀 자동 풀스팬. (composer.deriveGridBalanceCss)

### 3.6 이미지 배치 시맨틱스 `[가드+지시]`
- 라이프스타일/연출컷 → hero·feature·story·usage·closing만. 표·성분·FAQ·CS는 텍스트 주도(이미지 금지). `[가드]`
- 누끼 → 제품 포커스 슬롯만, 무드 배경 금지. 업로드 원본 → ingredient/detail/spec 행별 소형 슬롯만. `[가드]`
- 같은 이미지 URL 페이지당 1회. 세로 이미지를 와이드 슬롯에 금지. `[가드+지시]`
- 이미지가 부족하면 반복하지 말고 텍스트 주도 변형으로 전환. `[지시]`

## 5. 보조 요소 이용 규칙

### 5.1 장식(DECOR) `[부재→신설 방향]`
현행: 도트 그리드·체커 스트립·세로 라벨·넘버 워터마크가 전 페이지 공통 → **같은 잡지 다른 호 문제의 원인**. 방향(Phase 2): 장식 어휘를 형태 언어별로 분화한다 — sharp-editorial=헤어라인·룰 기반, soft-round=도트·원형, organic=불규칙 블롭, arch-serif=아치·프레임, neutral=최소 장식. 아트디렉터의 decorativeElements 산출을 장식 선택에 소비한다(현재 폐기됨).

### 5.2 아이콘 `[가드(렌더)+지시(선택)]`
자체 SVG 35종만. 의미 없으면 check/star/target 폴백. 라이브러리 혼용 금지.

### 5.3 styleTags `[정리 결정]`
250여 개 자유 태그 중 로직에 쓰이는 것은 `noimg-safe`뿐 — **styleTags는 "검색 힌트"로 지위를 명시**하고, 로직 관여 태그는 별도 필드로 승격해야 한다. 신규 변형은 기존 태그 재사용 우선, 신규 태그 발명 금지.

### 5.4 변형 CSS 하드코딩 예외 `[부재→신설]`
구조적 이유(금색 트로피·인증 그린 등 아키타입 고유색)로 토큰을 벗어나는 변형은 variant-meta의 `offPalette`를 명시해야 하며, 미신고 하드코딩은 결함으로 취급한다.

## 8. 강제 현황 대장 — Phase 1 승격 우선순위

1. **아트디렉터 Zod 게이트 신설** (폰트 화이트리스트·HEX 형식·shapeLanguage enum·전략 어휘) — 위반 침묵 통과의 근본 차단

6. **이모지 정규식 사전 차단** (LLM 판단 의존 제거)
7. §2.2 전략 어휘·§2.3 다양성 규칙 프롬프트 반영 (Phase 2와 연계)
